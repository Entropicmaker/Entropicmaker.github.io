# 预览与上传更新

## 1. 打开正确目录

在终端执行：

```bash
cd '/Users/linzii/Documents/个人博客搭建'
git status --short --branch
node -v
```

项目工作流使用 Node.js 22。现有电脑依赖可用就继续使用；新电脑按项目锁文件安装依赖：

```bash
npm ci
```

安装一次后，平时改文章无需重复安装。不要删锁文件或顺手升级依赖来处理普通内容问题。

## 2. 本地预览

```bash
npm run dev
```

打开终端打印的 Local 地址，通常是 `http://localhost:4321/`。保存文章后预览会更新。结束时按 `Ctrl+C`。

正式效果和搜索要这样检查：

```bash
npm run check
npm run build
npm run preview
```

前两个命令都成功后再打开 preview 打印的地址。`build` 会生成 `dist/` 和 Pagefind 搜索索引；`dev` 下不保证有可用的搜索索引。生产预览也会隐藏草稿。

## 3. 提交并上传

先确认只包含本次文件。以下以 `my-field-note.md` 和对应图片为例，替换成真实路径；没有图片就省略那行。

```bash
git diff --check
git diff
git status --short --branch
git add src/content/posts/my-field-note.md
git add public/images/my-field-note/
git diff --staged
git commit -m 'docs: 更新地理学习笔记'
git push origin main
```

这里假设当前分支就是 `main`。若状态显示其他分支，交给 skill 处理当前分支的合并与发布，不要误把旧的 `main` 推上去。不要使用 `git add .` 把无关文件混进本次更新。

如果提示远程有新提交而拒绝推送，不要强推。先保留本地修改，让 skill 检查并合并远端更新。

## 4. 等网页更新完成

打开 [博客 Actions](https://github.com/Entropicmaker/Entropicmaker.github.io/actions)，找到本次提交对应的“构建并部署到 GitHub Pages”。

必须等“构建静态网站”和“发布到 GitHub Pages”都成功，再用部署结果里的地址检查首页、新文章、图片和附件。推送成功只说明代码已上传，不等于网页已更新。

当前 `.github/workflows/deploy.yml` 在 `main` 分支 push 后自动部署。无需手工上传 `dist`，也无需每次重新配置域名。

如果需要更新 CodeVision，则在它自己的目录独立提交与部署。博客的 Git 不会包含该嵌套仓库。

## 一次更新的完成标准

- 本地检查和构建成功。
- 本次文件已经提交并推送。
- Actions 对应提交的构建与部署成功。
- 手机／平板能打开文章和附件，搜索能找到已公开正文。

工作流机制可参考 [GitHub Pages 自定义工作流官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)；本项目命令以仓库 `package.json` 为准。
