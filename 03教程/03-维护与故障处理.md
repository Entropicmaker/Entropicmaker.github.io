# 维护与故障处理

## 常用修改位置

- 站名、简介、作者：`src/data/site.ts`。
- 新留言：`src/data/messages.ts`。
- 项目展示：`src/data/projects.ts`。当前数组为空，没有占位项目，顶部入口会自动隐藏；以后添加真实项目数据即可重新显示。
- 分类说明：`src/data/categories.ts`；文章会自动列入首页和文章目录的对应分组，不再生成单独的分类展示页。
- 公共导航、页脚：`src/components/Header.astro`、`Footer.astro`。
- 首页结构：`src/pages/index.astro`、`src/components/ArticleIndex.astro`。
- 公共样式：`src/styles/global.css`；课件与关系图另见 `article-widgets.css`。当前默认使用原主站浅色设计，不随系统切换深色。
- 搜索：中文查询使用自动生成的公开文章文本索引，英文使用 Pagefind；发布文章后重新构建即可，不用手动改索引。

日常内容更新优先改 Markdown 和数据文件。改布局时让 skill 明确修改范围，并检查手机和平板。

## 文章没有出现

先看 `draft` 是否仍为 `true`，文件是否在 `src/content/posts/`，文章信息是否通过 `npm run check`。再确认此次提交已推送，并且 Actions 成功。

目前没有“到日期自动发布”的机制。填写未来的 `pubDate` 也不能代替草稿控制；`draft: false` 的文章在构建后就可能公开。

## 图片或附件打不开

检查实际文件是否存在、大小写是否一致、是否已加入提交。正文路径应类似 `/images/my-field-note/map.webp`，不含 `public/` 或电脑目录。先在生产预览检查，再看线上结果。

## 搜索不工作

先 `npm run build` 再 `npm run preview`。只有开发服务器时，缺少索引不一定是故障。线上仍异常时检查 Actions 中生成 Pagefind 的步骤。

搜索主要读取生成网页里的文本；仅链接一个 PDF 不等于 PDF 内容已进入搜索。

## 页面看起来没有更新

先核对 Actions 是否对应最新提交。成功后刷新页面或换一个新标签页核查；仍旧不对时记录页面 URL、提交号和问题现象交给 skill。

## 构建报错

复制最先出现的文件名、行号与错误文字给 skill。常见原因是分类拼错、缺少标题／描述／日期、MDX 标签没有闭合。检查失败时先修复，不要为了发布而跳过检查。

## 发错了怎么恢复

少量文字错误：改回正确文字，重新检查、提交、推送。

整次更新有问题：先 `git log --oneline -5` 找到对应提交，让 skill 使用 `git revert` 撤回那次提交，解决冲突后检查构建，再正常推送。撤回会新增一个可追溯提交；不要执行 `reset --hard` 或强推覆盖历史。

把文章改成草稿并重新部署可以从网页下架，但公开仓库和历史可能仍留有内容。密钥等敏感数据从一开始就不要上传。

## 轻量维护节奏

每次发布：打开新文章、点图片／附件、在平板看一次。

每月：检查坏链接与失败的 Actions；依赖更新单独处理，先构建再发布。不要把改正文和大规模升级混成同一次更新。

备份：推送只保存已提交文件；未提交稿件和未纳入 Git 的材料另做本地备份。
