# 发布或修改文章

## 1. 新建文章

复制 `templates/post-template.md` 到 `src/content/posts/`，重命名为英文短名，例如 `my-field-note.md`。这个名字决定网址：`/posts/my-field-note/`，发布后尽量不改名。

最小可用内容如下。日期改成实际日期；示例先保持草稿。

```markdown
---
title: 我的地理学习笔记
description: 记录本次学习的主要问题、方法与结论。
pubDate: 2026-11-09
draft: true
category: geography
tags: [学习笔记, 遥感]
---

用一小段话交代这篇文章讲什么。

## 问题

这里写正文。

## 方法

这里写过程。

## 结论

这里写结论与不足。
```

文件最前面的两行 `---` 之间是文章信息，必须保留。正文从第二行 `---` 之后开始。中文冒号 `：` 不能代替字段后的英文冒号 `:`；标题包含英文冒号时可用引号包住整个标题。

一级分类只能选下面一个英文值：

- `geography`：地理科学。
- `computer-science`：计算机科学。
- `geocomputing`：交叉研究／地理计算。
- `daily`：日常。

`subcategory`、`series`、`cover`、`readingTime` 都可暂不填写。普通文章用 `.md`；只有需要嵌入课件等组件才使用 `.mdx`。

## 2. 加图片和附件

在电脑里创建 `public/images/my-field-note/`，把图片放进去，例如 `map.webp`。正文写：

```markdown
![研究区位置图](/images/my-field-note/map.webp)
```

附件放 `public/files/my-field-note/notes.pdf`，正文写：

```markdown
[下载配套笔记 PDF](/files/my-field-note/notes.pdf)
```

网页路径不带 `public`，也不能写电脑上的 `/Users/...`。文件名大小写必须一致。上述以 `/` 开头的路径适用于当前根路径博客；以后若迁移到子路径，需要一起调整文章内资源路径。

图片建议用清晰且适当压缩的 WebP／JPEG。多图、课件可让 skill 批量整理并检查链接。PDF／PPTX 上传为附件后只提供文件链接，不会自动变成可搜索的正文；需要网页阅读时另写 Markdown，或明确要求转换。

## 3. 修改旧文章

直接打开原 `.md` 修改内容，保留原文件名和 `pubDate`。实质更新时添加或修改：

```yaml
updatedDate: 2026-11-09
```

替换图片可以保留原路径；如浏览器仍显示旧图，刷新后再检查，或给新版图片换一个文件名并同步更新正文链接。

## 4. 发布前

完成后把 `draft: true` 改成 `draft: false`，再执行检查、构建和上传。

开发预览会显示草稿，正式构建会排除草稿。这只控制网页显示：若把草稿提交到公开 GitHub 仓库，源文件仍可能被访问。未公开内容先留本地。

确认标题、日期、分类正确，图片有说明，附件能打开。正文使用 `##`、`###` 建立层级，通常不再重复写一个 `#` 文章标题。
