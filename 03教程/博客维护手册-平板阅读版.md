# 博客维护手册

版本：2026-11-09。适用项目：Linzii的地理小站（Astro + GitHub Pages）。

日常流程：修改源文件 → 本地检查 → 提交推送 → 等待部署成功 → 网页复查。

电脑目录：`/Users/linzii/Documents/个人博客搭建`。文章目录：`src/content/posts/`；图片和附件：`public/`。本教程目录 `03教程/` 不会自动发布成网页。

本文件由四篇短教程合并，便于一次上传到平板阅读工具；保留了全部操作内容。教程不等于已上传或已部署。

## 发布或修改文章

### 1. 新建文章

复制 `templates/post-template.md` 到 `src/content/posts/`，重命名为英文短名，例如 `my-field-note.md`。这个名字决定网址：`/posts/my-field-note/`，发布后尽量不改名。

最小可用内容如下。日期改成实际日期；示例先保持草稿。

```markdown
---
title: 我的地理学习笔记
description: 记录本次学习的主要问题、方法与结论。
pubDate: 2026-11-09
draft: true
category: geography
tags: [学习笔记, 遥感]
---

用一小段话交代这篇文章讲什么。

### 问题

这里写正文。

### 方法

这里写过程。

### 结论

这里写结论与不足。
```

文件最前面的两行 `---` 之间是文章信息，必须保留。正文从第二行 `---` 之后开始。中文冒号 `：` 不能代替字段后的英文冒号 `:`；标题包含英文冒号时可用引号包住整个标题。

一级分类只能选下面一个英文值：

- `geography`：地理科学。
- `computer-science`：计算机科学。
- `geocomputing`：交叉研究／地理计算。
- `daily`：日常。

`subcategory`、`series`、`cover`、`readingTime` 都可暂不填写。普通文章用 `.md`；只有需要嵌入课件等组件才使用 `.mdx`。

### 2. 加图片和附件

在电脑里创建 `public/images/my-field-note/`，把图片放进去，例如 `map.webp`。正文写：

```markdown
![研究区位置图](/images/my-field-note/map.webp)
```

附件放 `public/files/my-field-note/notes.pdf`，正文写：

```markdown
[下载配套笔记 PDF](/files/my-field-note/notes.pdf)
```

网页路径不带 `public`，也不能写电脑上的 `/Users/...`。文件名大小写必须一致。上述以 `/` 开头的路径适用于当前根路径博客；以后若迁移到子路径，需要一起调整文章内资源路径。

图片建议用清晰且适当压缩的 WebP／JPEG。多图、课件可让 skill 批量整理并检查链接。PDF／PPTX 上传为附件后只提供文件链接，不会自动变成可搜索的正文；需要网页阅读时另写 Markdown，或明确要求转换。

### 3. 修改旧文章

直接打开原 `.md` 修改内容，保留原文件名和 `pubDate`。实质更新时添加或修改：

```yaml
updatedDate: 2026-11-09
```

替换图片可以保留原路径；如浏览器仍显示旧图，刷新后再检查，或给新版图片换一个文件名并同步更新正文链接。

### 4. 发布前

完成后把 `draft: true` 改成 `draft: false`，再执行检查、构建和上传。

新增文章会自动进入首页分组、文章目录、归档、标签、RSS 和搜索索引，没有五篇上限；不需要手动修改页面或篇数。搜索结果每页 20 条，可翻页查看全部。

开发预览会显示草稿，正式构建会排除草稿。这只控制网页显示：若把草稿提交到公开 GitHub 仓库，源文件仍可能被访问。未公开内容先留本地。

确认标题、日期、分类正确，图片有说明，附件能打开。正文使用 `##`、`###` 建立层级，通常不再重复写一个 `#` 文章标题。

## 预览与上传更新

### 1. 打开正确目录

在终端执行：

```bash
cd '/Users/linzii/Documents/个人博客搭建'
git status --short --branch
node -v
```

项目工作流使用 Node.js 22。现有电脑依赖可用就继续使用；新电脑按项目锁文件安装依赖：

```bash
npm ci
```

安装一次后，平时改文章无需重复安装。不要删锁文件或顺手升级依赖来处理普通内容问题。

### 2. 本地预览

```bash
npm run dev
```

打开终端打印的 Local 地址，通常是 `http://localhost:4321/`。保存文章后预览会更新。结束时按 `Ctrl+C`。

正式效果和搜索要这样检查：

```bash
npm run check
npm run build
npm run preview
```

前两个命令都成功后再打开 preview 打印的地址。`build` 会生成 `dist/` 和 Pagefind 搜索索引；`dev` 下不保证有可用的搜索索引。生产预览也会隐藏草稿。

### 3. 提交并上传

先确认只包含本次文件。以下以 `my-field-note.md` 和对应图片为例，替换成真实路径；没有图片就省略那行。

```bash
git diff --check
git diff
git status --short --branch
git add src/content/posts/my-field-note.md
git add public/images/my-field-note/
git diff --staged
git commit -m 'docs: 更新地理学习笔记'
git push origin main
```

这里假设当前分支就是 `main`。若状态显示其他分支，交给 skill 处理当前分支的合并与发布，不要误把旧的 `main` 推上去。不要使用 `git add .` 把无关文件混进本次更新。

如果提示远程有新提交而拒绝推送，不要强推。先保留本地修改，让 skill 检查并合并远端更新。

### 4. 等网页更新完成

打开 [博客 Actions](https://github.com/Entropicmaker/Entropicmaker.github.io/actions)，找到本次提交对应的“构建并部署到 GitHub Pages”。

必须等“构建静态网站”和“发布到 GitHub Pages”都成功，再用部署结果里的地址检查首页、新文章、图片和附件。推送成功只说明代码已上传，不等于网页已更新。

当前 `.github/workflows/deploy.yml` 在 `main` 分支 push 后自动部署。无需手工上传 `dist`，也无需每次重新配置域名。

如果需要更新 CodeVision，则在它自己的目录独立提交与部署。博客的 Git 不会包含该嵌套仓库。

### 一次更新的完成标准

- 本地检查和构建成功。
- 本次文件已经提交并推送。
- Actions 对应提交的构建与部署成功。
- 手机／平板能打开文章和附件，搜索能找到已公开正文。

工作流机制可参考 [GitHub Pages 自定义工作流官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)；本项目命令以仓库 `package.json` 为准。

## 维护与故障处理

### 常用修改位置

- 站名、简介、作者：`src/data/site.ts`。
- 新留言：`src/data/messages.ts`。
- 项目展示：`src/data/projects.ts`。当前数组为空，没有占位项目，顶部入口会自动隐藏；以后添加真实项目数据即可重新显示。
- 分类说明：`src/data/categories.ts`；文章会自动列入首页和文章目录的对应分组，不再生成单独的分类展示页。
- 公共导航、页脚：`src/components/Header.astro`、`Footer.astro`。
- 首页结构：`src/pages/index.astro`、`src/components/ArticleIndex.astro`。
- 公共样式：`src/styles/global.css`；课件与关系图另见 `article-widgets.css`。当前默认使用原主站浅色设计，不随系统切换深色。
- 搜索：中文查询使用自动生成的公开文章文本索引，英文使用 Pagefind；发布文章后重新构建即可，不用手动改索引。

日常内容更新优先改 Markdown 和数据文件。改布局时让 skill 明确修改范围，并检查手机和平板。

### 文章没有出现

先看 `draft` 是否仍为 `true`，文件是否在 `src/content/posts/`，文章信息是否通过 `npm run check`。再确认此次提交已推送，并且 Actions 成功。

目前没有“到日期自动发布”的机制。填写未来的 `pubDate` 也不能代替草稿控制；`draft: false` 的文章在构建后就可能公开。

### 图片或附件打不开

检查实际文件是否存在、大小写是否一致、是否已加入提交。正文路径应类似 `/images/my-field-note/map.webp`，不含 `public/` 或电脑目录。先在生产预览检查，再看线上结果。

### 搜索不工作

先 `npm run build` 再 `npm run preview`。只有开发服务器时，缺少索引不一定是故障。线上仍异常时检查 Actions 中生成 Pagefind 的步骤。

搜索主要读取生成网页里的文本；仅链接一个 PDF 不等于 PDF 内容已进入搜索。

### 页面看起来没有更新

先核对 Actions 是否对应最新提交。成功后刷新页面或换一个新标签页核查；仍旧不对时记录页面 URL、提交号和问题现象交给 skill。

### 构建报错

复制最先出现的文件名、行号与错误文字给 skill。常见原因是分类拼错、缺少标题／描述／日期、MDX 标签没有闭合。检查失败时先修复，不要为了发布而跳过检查。

### 发错了怎么恢复

少量文字错误：改回正确文字，重新检查、提交、推送。

整次更新有问题：先 `git log --oneline -5` 找到对应提交，让 skill 使用 `git revert` 撤回那次提交，解决冲突后检查构建，再正常推送。撤回会新增一个可追溯提交；不要执行 `reset --hard` 或强推覆盖历史。

把文章改成草稿并重新部署可以从网页下架，但公开仓库和历史可能仍留有内容。密钥等敏感数据从一开始就不要上传。

### 轻量维护节奏

每次发布：打开新文章、点图片／附件、在平板看一次。

每月：检查坏链接与失败的 Actions；依赖更新单独处理，先构建再发布。不要把改正文和大规模升级混成同一次更新。

备份：推送只保存已提交文件；未提交稿件和未纳入 Git 的材料另做本地备份。

## 让 skill 处理与在平板阅读

### 先分清两种“上传”

博客发布：把文章、图片和附件放进博客源码，提交到 GitHub，等 Pages 部署。

Linote 阅读：把教程同步到你已经使用的笔记库或阅读服务，供平板查看。它与 GitHub 发布是两个独立动作。

本次只准备教材文件；没有发现可直接调用的 Linote 上传工具，也未验证 Linote 的具体导入入口，因此没有编写未经确认的按钮步骤。后续使用你实际连接的上传 skill，并让它核实目标库和导入格式。

### 让 skill 发布一篇文章

复制下面内容，补上材料和标题。这里的“上传”明确包含正式发布。

```text
请把我提供的材料整理为博客文章并发布。
项目：/Users/linzii/Documents/个人博客搭建
先读 03教程/00-从这里开始.md 和 templates/post-template.md。
标题：填写标题
分类：geography / computer-science / geocomputing / daily 四选一
材料：填写文件路径或本次附件
保留原意；不确定的事实不要编造。
文章放 src/content/posts；配图和附件放 public 下的对应目录。
如果是更新已有文章，保留原文件名和 pubDate，填写 updatedDate。
不要关联编程网站，也不要把教程和无关文件一起上传。
完成后运行 npm run check、npm run build，检查图片与附件路径。
确认本次差异后只提交本次文件，正常推送 main，等待 Actions 构建和部署成功。
最后给我文章网址、提交号、部署结果和仍需处理的问题。
```

只想看草稿时，把开头改成“整理为本地草稿”，把末尾的提交发布步骤改成“保持 draft: true，不提交、不推送，给我本地预览”。

### 让 skill 更新网站界面

```text
请修改博客的【说明具体位置和目标】。
项目：/Users/linzii/Documents/个人博客搭建
先检查当前 Git 改动，保留已有文章 URL 和内容。
按 docs/READABILITY_REDESIGN.md 的阅读优先原则处理。
检查手机、平板、桌面，以及深浅主题、导航、搜索和文章排版。
先完成本地修改和预览，给出变更摘要与检查结果。
本次不推送上线。
```

需要上线时，明确补充“检查通过后提交本次文件、推送并等待部署完成”。

### 把这套教程同步到 Linote

优先选用 `03教程/博客维护手册-平板阅读版.md`。它是纯 Markdown 单文件，使用普通标题、列表、代码块，不依赖 Obsidian 双链、插件、MDX 或本地图片。

```text
请使用我已配置的笔记上传 skill，将下面的教材同步到我在平板 Linote 阅读的笔记库：
/Users/linzii/Documents/个人博客搭建/03教程/博客维护手册-平板阅读版.md
标题：博客维护手册
目标目录：03教程（如果目标库有同名目录，优先使用）
请先核实实际支持的导入格式和目标库。
保留中文标题、顺序、代码块、链接和版本日期。
如果已有同名笔记，比较后更新，避免重复导入。
不要把教材作为公开博客文章发布。
完成后给出目标笔记链接，并确认平板端可读；无法验证时明确说明。
```

若已连接的工具不能读取本地路径，可把这个单文件作为附件交给它。首次导入后在平板检查：标题目录、代码换行、中文标点、链接；确认是否支持离线，再决定要不要另存离线副本。

以后修改任一短教程时，同时更新合并版，避免 skill 导入旧内容。
