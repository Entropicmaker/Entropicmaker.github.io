# 首页结构重整与内容坐标动效修改方案

日期：2026-10-17

审查基线：正式版 v006，提交 `fc6b485`。

状态：已获用户确认，并按此方案实施为 v007。以下保留方案与原审查依据，实际实现和验证见 [视觉版本记录](VISUAL_VERSIONS.md) 的 v007 条目。

## 1. 核心判断

当前首页缺少统一的信息组织。首屏采用视觉概念稿的构图，下面继续使用原博客的文章和项目组件；去掉卡片背景、边框后，组件内部的间距、信息量和旧装饰仍然保留，栏目之间的主次关系没有重新建立。

这会让访客感到：上面是一张个人视觉海报，下面是一长串同等重要的内容。需要先明确“站点身份 → 选择内容 → 开始阅读 → 延伸到项目”的顺序，再安排视觉与动效。

推荐方向：**用清楚的博客结构组织内容，以地理绿、观测图形和局部擦出动效表达风格。文章浏览成为首页的主要任务。**

本轮检查了当前正式构建的桌面整页、手机首屏、组件和切换脚本。以下坐标为页面顶部起算的 CSS 像素，属于当前内容与测试尺寸下的实测值。

| 问题 | 当前表现 | 对阅读的影响 |
| --- | --- | --- |
| 真实内容出现偏晚 | 1280×720 桌面下，简介区高约412px；“最新文章”从约891px开始。390×844 手机下，首篇坐标文章标题从约857px开始 | 首屏主要看到站名、地球和分类，尚未形成可阅读的内容中心 |

| 文章内容重复 | 同一篇《光合作用、Vcmax 与遥感：零基础学习课件》先出现在坐标区，又紧接着出现在最新文章首位 | 用户滚动后仍读到同一内容，难以判断两个区域的区别 |

| 项目区仍保留旧组件结构 | 四个项目分两行，单项约406–464px；保留独立图标、状态胶囊、成果分隔线和技术栈胶囊 | 文章区已经扁平化，项目区仍是另一种视觉语法，且占据约1073px高度 |

| 装饰与功能辨识不足 | 大量英文标注与小编号、淡色小点承担分类状态，导航入口也较多 | 信息看起来都像标注，缺少稳定、明显的操作锚点 |

问题的重点不是把留白全部填满，而是让栏目归属、内容分组、阅读路径和操作反馈变得明确。

## 3. 推荐的首页结构

### 3.1 页面顺序

```text
页头：统一站点标识 / 主要导航 / 搜索与主题 / 次级系列站点入口

紧凑的站点简介
  左：站名 + 一句内容定位
  右：缩小的观测地球，与文字形成一组

文章与记录                                      全部文章 ↗
  桌面左侧：内容坐标             桌面右侧：文章内容主区
  · 全部记录（复位入口）          当前范围 + 实际文章数
  · 地理科学 01                 一篇重点文章
  · 计算机科学 02               其余文章的紧凑列表
  · 地理计算 03                 进入该栏目 / 查看更多
  · 日常 04

项目精选                                       项目档案 ↗
  一到两个有实际内容可访问的项目

主题索引：少量常用主题，以一行或两行文字链接呈现

页脚：作者署名 / 归档 / 关于 / RSS / 站点关系
```

“全部记录”是筛选复位入口，不是第五个内容坐标。默认展示全站最近记录，四个既有坐标继续保留。

### 3.2 每一部分只承担清楚的任务

| 区域 | 任务 | 修改建议 |
| --- | --- | --- |
| 页头 | 说明这里是哪个网站、可以去哪里 | 建议统一使用 Linzii 的地理小站标识；“选择性失忆”保留为作者署名。主要入口收敛为文章、项目、归档、留言、关于；分类与标签由文章浏览和索引承接，原地址保留 |
| 简介 | 让新访客知道博客关注什么 | 桌面简介区目标约220–280px，地球约200–240px；保留站名与地理图形。个人签名保留，但内容定位应先于装饰英文和签名 |
| 文章与记录 | 分类、发现并打开文章 | 内容坐标直接控制这一份文章内容流；精选与普通列表属于同一个栏目组，不再重复展示同一篇文章 |
| 项目精选 | 展示可访问的成果 | 优先展示有真实页面的项目。只有一个成熟入口就展示一个，不为凑满网格增加条目；无详情页的项目可在项目档案中说明进展 |
| 主题索引 | 补充检索路径 | 从大号胶囊云改为克制的文字链接，默认5–8项。现有数字是文章数，不应被表述为访问热度 |
| 页脚 | 提供作者和站点背景 | 保留完整站点关系与次级入口，降低它们在主导航中的竞争 |

## 4. 版式与内容规则

### 4.1 建立统一的网格和层级

- 主容器沿用约1120px，内部按12列组织；桌面文章区约3列给坐标导航、9列给内容。各栏目、标题和分隔线遵守共同对齐线。
- 主站名建议44–52px；栏目标题24–28px；重点文章24–26px；普通文章20–22px；正文摘要15–16px；日期等辅助信息12–13px。最终按实际字长校准。
- 栏目之间用较大的间距和细分隔建立边界，栏目内部用更紧的间距表达归属。减少连续的全宽横线和漂浮的小标注。
- 正常的矩形排版容器可以存在；视觉重点放在文字、图形和空间组织。避免把每个模块处理成同等体积的独立大方块。
- 地理绿、深青、灰绿底和少量暖棕继续承担原有角色。主内容使用清楚的文字对比，英文与编号作为辅助，不再主导导航识别。

### 4.2 合并文章展示，消除重复

- 首页只保留一份文章数据流。“全部”按时间排序，坐标选择按对应分类筛选。
- 每个状态由一篇重点文章和剩余列表组成，重点文章从列表中排除；重点优先使用明确标记的精选，没有精选则使用该范围最新一篇。
- 普通文章行只保留标题、1–2行摘要、日期、分类及必要的阅读时间。完整系列、标签和详细元数据交给文章页与索引页。
- 桌面普通行目标约120–160px，按内容自然伸缩；取消从旧卡片继承的无意义最小高度和大间距。
- 当前只有五篇文章，按真实数量呈现，不制造占位内容。分类无文章时展示明确的空状态和返回全部入口；相关项目必须有真实关联并注明“项目”，不能直接代替文章。

### 4.3 手机重新编排

- 左侧坐标导航转为两列、两行的清楚入口，“全部”留在文章区标题旁；不依赖横向滑动才能发现某一类。
- 地球不再独立占据一整行220px；采用缩小、侧置或局部裁切的辅助构图，给文章入口留出首屏空间。
- 以390×844为主要检查尺寸：首屏应能看到站点身份、内容坐标和第一篇文章标题。320px下允许自然换行，不能靠缩小字号硬塞内容。
- 项目与辅助索引自然下排，重要入口无需悬停；触屏目标保持易于点击。

## 5. 内容坐标：从右往左擦出的动效方案

### 5.1 明确动作定义

本轮按“从右往左擦出”理解你的要求：**擦除／揭示边界从内容区最右侧走向最左侧，旧内容沿边界消退，新内容在边界经过后显现。文字基本保持最终排版位置。**

目前脚本主要是旧内容淡出、小幅位移、新标题逐词上浮，同时地球放大和转动；这些动作应让位给清楚的横向擦出。

四个坐标无论向前或向后选择，都采用右→左的固定方向。左侧导航和整页布局保持稳定，动效主要发生在文章内容主区。

### 5.2 三层关系

| 层次 | 行为 | 作用 |
| --- | --- | --- |
| 基础版面 | 背景、导航、栏目边界稳定 | 保留阅读方向和操作锚点 |
| 内容遮罩 | 新旧文章层使用相互补足的裁切范围，边界由右向左移动 | 让内容本身被擦出，而不是出现一块覆盖正文的滑块 |
| 局部强调 | 分类编号和少量标题笔画可沿同一方向短暂反色，错开20–40ms | 增加平面设计层次，保持地理绿主题 |

第一版先把遮罩方向与内容关系做好，再视实际画面决定是否加入轻微倾斜边缘。斜切只作用于移动边界，不让整块标题和正文倾斜。停止当前大背景分类字、逐词跳入和明显的地球缩放，以免多个动作争抢注意力。

### 5.3 建议节奏

建议一次约420ms，作为首轮试做参数；它们是为博客制定的参数，不是 P3 原作的官方数值。

| 时间 | 动作 |
| --- | --- |
| 0–60ms | 选中坐标立即更新文字颜色与小面积强调，提供即时反馈 |
| 20–300ms | 主要文章层从右向左擦出；新旧层在同一边界交接，不留一段整块空白 |
| 50–340ms | 摘要、日期和编号跟随同方向揭示，保持短暂错拍 |
| 300–420ms | 细微残余运动收束，画面恢复静止；不增加第二次弹跳或重新淡入 |

地球可在后续预览中尝试极轻的外环响应，但第一版优先验证文字擦出。日常使用中，访客应首先感到“切换清楚而迅速”。

### 5.4 实现与交互约束

- 可使用双层内容和 `clip-path`／遮罩。新层的可见区域从右边开始增长；旧层的可见区域从右边开始缩减，两者的边界同步向左。
- 标题与摘要以各自实际内容范围计算遮罩，避免先擦过一大片空白才触及文字。
- 新旧层共同使用一个动画时钟。旧层仅用于视觉过渡，移除其重复链接焦点，并对读屏隐藏。
- 筛选按钮持续可响应，连续点选时取消旧过渡，以最后一次选择为准；选中坐标、可见内容和最终链接必须一致。
- 遮罩本身不改变布局尺寸。新旧内容高度不同时只在过渡期间协调容器高度，结束后恢复自然排版，避免永久固定高度制造空白。
- 焦点留在用户选择的坐标上，辅助技术在切换完成后收到一次结果更新。减少动态效果时直接更新内容，不播放复杂擦出。
- 内容坐标采用右→左；现有入场保留右下→左上的弧面转色，两者各自表达不同操作，不强行合成同一种动作。

## 6. P3R、莱茵生命与博客之间的分工

- **莱茵生命的参考价值**用于静态组织：明确的索引、分组、细线、留白和档案层级。高级感应由内容组织产生，而不是依靠降低全部文字的对比度。
- **P3／P3R 的参考价值**用于局部画面组织与切换：稳定的操作区域、遮罩揭示、局部反色、文字与图形的层次关系。主要配色继续服从博客的地理绿。
- P3R 开发者访谈谈到水中浮游、透明与反射等主题，同时强调菜单响应和操作明确。对本博客的设计判断是：保留细腻的图文关系，把频繁切换做得清楚、迅速，不把每次分类操作都做成片头演出。[开发者访谈](https://www.famitsu.com/news/202311/29325647.html)

原参考：[P3联动PV](https://www.bilibili.com/video/BV1zCtA6mEay/)、[莱茵生命特别映像](https://www.bilibili.com/video/BV1rr4y1b7sz/)、[P3R官方资料](https://p3re.jp/)。本方案的首页结构、遮罩编排和时长属于针对博客的设计提案。

## 7. 后续修改顺序

1. **先完成静态结构。** 调整身份区、坐标导航、文章主区、项目精选和主题索引；关闭动效检查整页是否已经像清楚的博客。
2. **再单独验证擦出。** 在新文章区中实现右→左双层遮罩，检查长短标题、空栏目、连续点选和手机换行。
3. **最后衔接入场。** 简介和地球位置改变后，重新计算现有入场的最终落位，复测 v006 已修复的名字淡出；保持已确认的配色、文案与2.8秒节奏。
4. **保存候选 v007。** 保留 v006 标签与完整快照，新版另存源码与预览记录。先交付可检查的页面，再进行正式发布。

方案评审阶段未修改页面；经用户确认后实施，版本号为 v007。

## 8. 验收标准

- 访客能辨认：这是哪个网站、主要写什么、从哪里开始阅读、四个栏目如何切换。
- 1280×720桌面首屏能看到主要栏目入口、首篇文章标题和至少一行摘要；390×844手机首屏能看到首篇标题。
- 首页同一个文章链接不会以两篇主要文章的身份重复出现；空栏目不混入无关项目。
- 首页文章与项目使用统一的对齐、字号、间距和链接语法；目录结构在关闭动画时仍然成立。
- 右→左擦出的方向清楚，内容的实际像素被裁切揭示；不出现实心矩形滑过、逐词蹦入或空白停顿。
- 快速切换后，坐标、标题、列表、计数和链接一致；长标题与手机换行不被永久裁切。
- 入场收尾不回闪，两个已删除的按钮不重新出现。
